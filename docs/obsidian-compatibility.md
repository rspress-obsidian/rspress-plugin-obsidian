# Obsidian compatibility

This plugin publishes a **subset** of an Obsidian vault as an Rspress site. It reads vault files — Markdown notes, attachments, `.canvas` boards, `.base` files, Excalidraw drawings — and rewrites the Obsidian Markdown dialect into HTML at build time. It is not an Obsidian implementation: there is no plugin API, no appearance configuration (themes, CSS snippets, workspaces), and no live preview or in-browser editing of vault files. The most used community and core plugins (Dataview, Tasks, Kanban, Excalidraw, Bases, Templater) are reimplemented as build-time renderers that read the vault's own plugin settings. Anything that depends on Obsidian's editor, its plugin runtime, or its sync service is out of scope, and the tables below say so rather than implying support.

Every row is grounded in the source file named in its caveat. Where a row is `partial`, the caveat names the concrete limitation.

| Status | Meaning |
| --- | --- |
| supported | Implemented, with the caveat noted where one exists |
| partial | Implemented for a subset, or with a known limitation named in the caveat |
| not supported | Not implemented |

Feature toggles decide most of this surface: wikilinks, comments, highlights, footnotes and block anchors are always on; Markdown links and case-insensitive lookup default to `true`; everything else (callouts, transclusion, media embeds, tag links, tag pages, backlinks, Dataview, daily notes, math, Mermaid, Tasks, Kanban, Excalidraw, Bases, Templater) is opt-in. See `src/markdown/normalize-options.ts` (`normalizePluginOptions`) for the defaults.

## Markdown dialect

| Feature | Status | Caveat |
| --- | --- | --- |
| Wikilinks `[[Page]]`, `[[Page\|Alias]]` | supported | Always on. Targets may be vault-relative, note-relative (`./`, `../`), a path suffix (`[[sub/Note]]` finds `a/sub/Note.md` without fuzzy matching), a bare basename, a frontmatter title or an alias — see `src/markdown/resolve-wikilink.ts` (`resolveWikiLink`). The link text is Obsidian's display text: the alias, else the target exactly as typed (`[[2024-01-15]]` shows `2024-01-15`, `[[my_note]]` shows `my_note`), with a subpath shown as `Note > Heading` / `Note > ^id` and a same-page `[[#Heading]]` as `Heading` (`src/markdown/utils.ts`, `wikiLinkDisplayText`). Inside a table the escaped alias pipe `[[Page\\|Alias]]` splits the alias too. |
| Heading and block anchors `[[Page#Heading]]`, `[[Page#^id]]`, `[[#Heading]]` | supported | A heading matches exactly — by its explicit `{#id}`, its rendered id, its text as rendered or as written, or Obsidian's link form of it (`#`, `\|`, `^`, `:`, `%`, `[`, `]`, `\` read as spaces, so `[[Note#Step 1 Setup]]` finds `## Step 1: Setup`), case-insensitively. A prefix or a fragment of a heading no longer resolves to it: a renamed heading is reported through `onBrokenLink` instead of landing on an unrelated one. `[[Note#A#B]]` is a path: `B` must sit under an `A` (levels in between may be skipped). Heading ids are the ones the rendered page carries — comments dropped, wikilinks as their display text, math as its TeX, intraword `_` kept (`## my_function` → `#my_function`), one counter per page with explicit ids not consuming it (`src/markdown/heading-text.ts`; `src/markdown/resolve-wikilink.ts`, `findHeading`). Block ids are compared case-insensitively after whitespace normalization. |
| Vault search `[[##query]]`, `[[^^query]]` | supported | Resolved while compiling against every page's headings (`##`) or block ids (`^^`). A query matching exactly one target becomes a normal link; a query matching several renders an inline `<WikiPicker>` — a button that opens a filterable list of the matches, the way Obsidian offers a picker instead of refusing the link. The candidates are resolved at build time and travel in the component's attributes, so the picker works on a static export with no runtime data module; a query matching nothing stays an unresolved-link marker (`src/markdown/resolve-wikilink.ts`, `resolveVaultSearch`; `src/markdown/runtime/WikiPicker.tsx`). |
| Escapes inside wikilinks (`\|`, `\#`, `\^`, `\[`, `\]`) | supported | Those five characters only. Wikilinks are a tokenizer construct, so an escaped `]` never closes the link and a name holding emphasis delimiters — `[[__init__]]`, `[[*draft*]]`, `[[Note\|*alias*]]` — is a link, not emphasis (`src/markdown/syntax.ts`; `src/markdown/parse-wikilink.ts`). |
| Unresolvable links | supported | A dimmed span keeps the readable label — the alias, else the target as typed — with the raw `[[…]]` syntax and the reason in its attributes (`src/markdown/remark-wikilink.ts`, `createUnresolvedNode`). |
| Ambiguous links | supported | A name several files share resolves the way Obsidian picks: the match in the linking note's own folder, else the shortest vault path, else the alphabetically first. `onAmbiguousLink` (default `"warn"`; it was `"error"` before) reports the choice and the alternatives; set it to `"error"` to fail the build instead (`src/markdown/resolve-wikilink.ts`, `pickMany`). |
| Note embeds `![[Page]]` and transclusion | supported | Opt-in via `enableTransclusion`. The embedded file is re-run through the same pipeline, so headings, callouts, footnotes and tags inside it render normally. Every id it emits — headings (which keep the ids their own page gives them), footnotes, block anchors — is prefixed per embed (`embed-1-…`), so the page never carries a duplicate id (`src/markdown/remark-wikilink.ts`, `renderPageEmbed`). |
| Transclusion subpaths `![[Page#Heading]]`, `![[Page#^id]]`, `![[#Heading]]` | supported | A heading section is found by the id the index resolved, so the second of two same-named headings and a nested `A#B` path embed the right section; it runs to the next heading of equal or higher level, ignoring frontmatter and fenced code. A block id takes the block above a standalone `^id`, or the whole paragraph (or list item with its children) carrying a trailing ` ^id`. A note may embed its own section with `![[#Heading]]` (`src/markdown/remark-wikilink.ts`, `extractHeadingSectionById`; `src/shared/transclusion.ts`). |
| Transclusion depth and cycles | supported | Depth is capped at 5. A cycle is detected on page *and* section, so only an embed already on the stack is refused (a section that embeds itself, a note that embeds itself whole); a refused embed becomes a link to its page plus a diagnostic (`src/markdown/remark-wikilink.ts`, `MAX_TRANSCLUSION_DEPTH`). |
| Media embeds | supported | Every format in Obsidian's accepted list, from one shared table both renderers read (`src/shared/media-exts.ts`): images `avif`, `bmp`, `gif`, `jpeg`, `jpg`, `png`, `svg`, `webp`; audio `3gp`, `flac`, `m4a`, `mp3`, `ogg`, `wav`; video `mkv`, `mov`, `mp4`, `ogv`, `webm`; and `pdf`. Sizing and captions follow Obsidian in both forms — `![[img.png\|300]]`, `\|300x200`, `![[img.png\|A caption\|300]]`, and on a markdown image `![300](img.png)`, `![300x200](img.png)`, `![A caption\|300](img.png)`. A PDF takes `#page=N` in the frame's `src` and `#height=N` as the frame height, in a `figure` with a caption bar naming the file and an "Open" link to it. Audio, video and PDF frames — and raw `<audio>`, `<video>`, `<source>` and `<iframe>` a note writes itself — carry the site `base`; images go through Rspress's `img` component, which adds it. A file missing from disk still emits a root-relative `src` and warns. `.webm` is rendered as video (`src/markdown/media.ts`, `src/markdown/rehype-raw-mdx.ts`, `src/canvas/utils/markdown.ts`). |
| Markdown images `![](img.png)` | supported | Resolved like an embed: next to the note, from the root, or by unique file name anywhere in the vault, percent-encoded and `<angle bracket>` paths included. Rspress turns each relative image into an import before plugins run, so the pass rewrites that import to the file it found (a path relative to the page, bundled like any Rspress image) and exempts relative urls from Rspress's dead-image gate (`markdown.image.checkDeadImages.excludes`, unless the site sets it); an image found nowhere is reported through `onBrokenLink` instead of failing the bundler. A sized image with a non-relative URL passes `sanitizeUrl` (`src/markdown/media.ts`, `processMarkdownImages`, `isPluginOwnedImageUrl`). |
| Callouts | supported | Opt-in via `enableCallouts`. Any type up to `]` — `[!my-type]`, `[!my_type]` — with `[!type\|metadata]` passed on as `data-callout-metadata`. Obsidian's documented aliases share their type's styling (`summary`/`tldr` → `abstract`, `hint`/`important` → `tip`, `check`/`done` → `success`, `help`/`faq` → `question`, `caution`/`attention` → `warning`, `fail`/`missing` → `failure`, `error` → `danger`, `cite` → `quote`): the class names the shared type and `data-callout` keeps the type as written, as Obsidian's DOM does. With no title the type is the title, capitalised (`Tip`). `+`/`-` produce `<details open>`/`<details>`, nesting is resolved innermost-first, the body is read with GFM, and every type Rspress's GitHub-alert transform claims (`important` included) is restored from source first (`src/markdown/callouts.ts`). |
| Unknown callout types | supported | A type outside the alias table keeps its own `callout-<type>` class and Obsidian's `data-callout` attribute, and falls back to Obsidian's `note` styling (blue card, pencil glyph) instead of a neutral placeholder. `todo` has its own blue card and checkbox glyph, and every bundled type ships a colour and a title glyph; restyle any type with the CSS variables Obsidian documents (`src/markdown/styles.css`; glyphs generated by `scripts/generate-icons.ts`). |
| Callout titles | supported | Title text is inline Markdown rendered by the same passes as the body: wikilinks resolve (a broken one is reported like any other), `==highlights==`, math and tags render, and `%%comments%%` are dropped; raw HTML in a title is dropped (`src/markdown/remark-wikilink.ts`, `renderInlineHtml`). |
| Tags | supported | Inline `#tag` (at least one non-numeric character required) and frontmatter `tags`/`tag` — a YAML list, or the legacy single string Obsidian splits on commas and spaces — merged per page. Inline tags are read from prose only: not from code spans, fences, comments, `[[#Heading]]` links, link destinations like `[x](#install)`, URLs or HTML attributes (`src/markdown/page-links.ts`). An escaped `\#word` is literal text, as in Obsidian, in the index and on the page alike — the parser records each escaped `#` so the tag pass leaves it alone, in callout bodies, quotes and lists too (`src/markdown/syntax.ts`, `obsidianEscapedHashes`). Tags are case-insensitive: one route per tag, `tagRoutePath` (`/tags/<lowercased tag>`), whatever the spelling. `enableTagLinking` rewrites inline tags into links to that route, which only exists when `enableTagPages` is also on; `a/b/c` also aggregates `a` and `a/b` (`src/markdown/tag-pages.ts`, `generateTagPages`). |
| Comments `%%…%%` | supported | Whole nodes between the delimiters are removed, including paragraphs and headings. Delimiters inside frontmatter, fenced code and inline code are ignored; an unclosed `%%` stays as written. Code spans pair the CommonMark way across a paragraph: an opener hides delimiters only up to the next run of the same length, and an unpaired run is literal text that silences nothing (`src/markdown/comments.ts`). |
| Commented-out headings | supported | The heading is removed from the body, the page outline and the search index. Rspress builds the outline and the index from its own parse of the source, before plugin remark plugins run, so the plugin drops the matching entries afterwards: by the `charIndex` Rspress records, or — when `search: false` leaves no offsets — by heading identity, reconciled against the live headings so a same-named live heading keeps its entry (`src/markdown/comments.ts`, `filterCommentedToc`; `modifySearchIndexData` and `extendPageData` in `src/markdown/index.ts`). |
| Highlights `==text==` | supported | A tokenizer construct paired like GFM's `~~`, so a highlight spans inline markup — `==**bold** text==`, `==see [[Note]]==` keeps a working link — and never fires inside code or math. `===` and longer runs are never markers. Rendered as `<mark>` (`src/markdown/syntax.ts`). |
| Footnotes `[^id]`, `[^id]: …`, `^[inline]` | supported | Label footnotes come from GFM (so a definition inside a code fence is code) and inline `^[…]` footnotes are matched by bracket depth at the phrasing level, so their content may hold Markdown, wikilinks and brackets; an unclosed `^[` stays literal text, and a footnote written inside `**bold**` keeps the bold (`src/markdown/inline-footnotes.ts`). Both kinds are numbered in one sequence by first reference and listed in that order, as Obsidian and GFM do; a repeated reference reuses its number (`fnref-1-2`). Definitions render through the same passes as the body (wikilinks, math, tags), each reference's `title` is the definition's visible text, and comments never reach either. Ids carry the document's prefix, so an embedded note's footnotes cannot collide with the host's (`src/markdown/footnotes.ts`). Canvas text cards render both forms too (`src/canvas/utils/markdown.ts`). |
| Math `$…$`, `$$…$$` | supported | Opt-in via `enableMath`. Tokenized by `micromark-extension-math` on the page's own parser, so `\$` is an escape, and `*`, `_`, `==`, `\{`, `\,` and `\\` inside a formula reach TeX untouched. Obsidian's rule holds: inline math may not begin or end with a space, so `$5 and $10` stays prose; `$$…$$` written inside a paragraph is display math. Callout bodies, footnotes and transclusions are re-parsed with the same tokenizer (`src/markdown/syntax.ts`). Two engines, chosen with `mathEngine`: `katex` (the default, with the mhchem contrib, so `\ce{H2O}` and `\pu{…}` work) and `mathjax`, Obsidian's own engine, an optional dependency (`bun add mathjax-full`). MathJax runs with its `safe` extension, so `\href{javascript:…}` and `\style{…url(…)}` are neutralised as KaTeX's `trust: false` does, and its glyph stylesheet is regenerated for every page, so a glyph first used on a later page is never blank. Malformed TeX renders as the engine's own inline error (`src/math.ts`; `src/markdown/inline-passes.ts`, `processMath`). |
| Mermaid | supported | Opt-in via `enableMermaid`, and `mermaid` is an optional peer dependency (`npm install mermaid`), so sites without diagrams do not install its ~100 MB. Without it the site still builds: the plugins alias the import to an empty module and print one install hint at build time, and each diagram stays visible as source, marked with `obsidian-mermaid-error` and `data-mermaid-unavailable` and titled with the install hint (`src/mermaid/install.ts`; `src/mermaid/blocks.ts`). Canvas text cards with Mermaid fences need the same package. Diagrams render in the browser, with mermaid's `securityLevel` configurable through `mermaidSecurityLevel` — `"strict"` (the default) runs mermaid's own sanitising pass and strips unsafe link URLs, so a `click` directive with a `javascript:` URL is removed rather than rendered as a live anchor; the looser levels allow what a strict build refuses. The level travels with each placeholder and configures the shared client instance. A failed or timed-out (10s) render keeps the raw source, marks the block as an error and logs a console warning (`src/mermaid/blocks.ts`). |
| Frontmatter / properties | supported | YAML and JSON, the two formats Obsidian's own Properties read; a document is matched on its frontmatter, not its extension. A `---js` marker is refused by a throwing engine stub rather than executed, and any other language marker is rejected before the parser runs — executing frontmatter is a Dataview feature, not Obsidian's, and the plugin interprets DataviewJS in a restricted interpreter instead. A refused or malformed block publishes the page with empty metadata and a console warning, so one bad header cannot fail a build. Keys read: `title`, `aliases`/`alias`, `tags`/`tag`, `cssclasses`/`cssclass`, `excerpt`, `publish` (`src/shared/frontmatter.ts`; `src/markdown/content-index.ts`). |
| `excerpt` | supported | Copied into the page description through Rspress's `extendPageData` hook, so the theme renders it as `<meta name="description">` and `og:description`. An explicit frontmatter `description` wins; without one, the excerpt overrides the auto-extracted first paragraph, and whitespace inside the excerpt is collapsed (`src/markdown/index.ts`). |
| `publish: false` | supported | Keeps a page out of the site wherever it lives. A **vault** page is dropped from the content index, so it is never routed or linkable. A **docs-root** page has its route removed from Rspress's route service, which takes the page out of the build, out of the auto-generated sidebar and nav (both derived from the routes) and out of the search index (built from the same route service). A page an explicit sidebar or nav config still lists keeps its entry there, so remove it from the config too. An attachment only a `publish: false` note references is not published either (`src/markdown/content-index.ts`; `src/markdown/index.ts`, `routeServiceGenerated`, `syncVaultAssets`). |
| Arbitrary frontmatter keys | supported | Read the way Dataview reads properties: a string that is exactly a date, a duration or a `[[link]]` becomes one, and every key is also reachable by Dataview's canonical name (lowercased, spaces to dashes, markup dropped), so `My Key` and `my-key` both resolve. A key written several times (frontmatter plus inline fields) holds a list of its values (`src/markdown/dataview-metadata.ts`, `extractDataviewMetadata`). |
| Markdown links into the vault `[label](note.md)` | supported | On by default (`enableMarkdownLinks`). Only `.md`/`.mdx` destinations are claimed; external URLs, pure anchors and extensionless routes are left to Rspress, and unresolvable destinations are reported through `onBrokenLink` (`src/markdown/remark-wikilink.ts`, `processMarkdownLinks`). |
| Reference-style links `[label][ref]` | supported | The `[ref]: Page.md` definition is rewritten, which fixes every reference to it at once (`src/markdown/remark-wikilink.ts`, the `definition` visitor in `processMarkdownLinks`). |
| Markdown embeds `![alt](note.md)` | supported | Inlined when `enableTransclusion` is on, otherwise rendered as a styled embed link; this works on the `<img>` element Rspress's own image transform creates too (`src/markdown/remark-wikilink.ts`, `processMarkdownEmbeds`). |
| Block IDs | supported | A standalone `^id` line and a trailing ` ^id` are indexed, and an empty `<span id="^id">` is emitted where the marker stood for the ids the index knows, so `[[page#^id]]` and block searches resolve. A `<span>`, not an `<a>`, because Rspress turns every `<a>` into a link to `/` and a stop in the tab order (`src/markdown/content-index.ts`; `src/markdown/inline-passes.ts`, `emitBlockAnchors`). |
| Headings and aliases as link targets | supported | Headings are indexed with the ids the page renders, plus explicit `{#custom-id}` (explicit ids win). Frontmatter titles and aliases are matched after exact path and file-name lookups; a legacy comma-separated `aliases: First, Second` string is two aliases (`src/markdown/content-index.ts`; `src/markdown/resolve-wikilink.ts`, `findHeading`). |
| `obsidian://` links | partial | Only `obsidian://open` resolves — `file` (or legacy `path`) with an optional `#Heading`, `%23Heading` or `subpath` parameter — and the `vault` parameter is ignored because one site publishes one vault. `search`, `new`, `hook-get-address` and any unparseable URI are left as written and reported through `onBrokenLink` (`src/markdown/remark-wikilink.ts`, `parseObsidianUriTarget`). |
| Standard Markdown and GFM | supported | Tables, task lists and the rest come from Rspress's own Markdown pipeline; this plugin is a remark pass layered on top of it, and the Obsidian constructs (`[[…]]`, `![[…]]`, `==…==`, `$…$`) are micromark extensions registered on that same parser, so they claim their characters before emphasis, escapes and links do (`src/markdown/syntax.ts`). |
| Task statuses `- [/]`, `- [-]`, `- [>]`, `- [?]`, `- [!]` | supported | Any one-character status renders as a checked task, as Obsidian draws it, with the character on the item as `data-task` (`""` for `[ ]`, `x` for `[x]`) for themes and snippets; the bundled stylesheet strikes through `x` and `-` and dims the in-progress statuses (`src/markdown/inline-passes.ts`, `processTaskStatuses`; `src/markdown/styles.css`). |
| Soft line breaks ("Strict line breaks" off) | supported | Obsidian's default reading view shows a single newline inside a paragraph as a line break. `strictLineBreaks` mirrors the setting: unset, vault pages follow Obsidian's default and docs-root pages keep CommonMark; `false` gives every page `<br>` breaks; `true` none (`src/markdown/inline-passes.ts`, `applySoftLineBreaks`). |

## Vault formats, canvas and graph

| Feature | Status | Caveat |
| --- | --- | --- |
| `.canvas` parsing | supported | JSON Canvas `text`/`file`/`link`/`group` nodes and edges with sides/ends/labels/colours. Fields the plugin does not know (another tool's `styleAttributes`, top-level metadata) are kept, so an editor export round-trips them; fields only the publisher writes (`resolvedFile`, `assets`, `notes`, `links`, and the `fileContent`/`assetUrl`/`isImage`… fields earlier versions wrote) are ignored in a source file and stripped from an export. A malformed **card** is dropped rather than failing the board, and each drop is reported by name and reason on the console; a duplicate id keeps the first, and an edge whose endpoint was dropped goes with it. Only a structurally broken document is a hard error, and then the raw board is still published (`src/canvas/parser.ts`, `parseCanvas`/`serializeCanvas`; `src/canvas/index.ts`). |
| Canvas rendering | supported | Presets 1–6 in Obsidian's light/dark palette; any colour (preset or custom) shows on the border over a translucent tint, and on a group's border and label. Groups paint below the edges and the edges below every other card, each band in array order (the spec's z-order). An edge with no `fromSide`/`toSide` attaches to the facing sides; labels sit on the curve's midpoint in a themed, multi-line box; arrow markers are unique per board instance. Link nodes embed the website in a sandboxed, lazy frame like Obsidian (`linkPreview: false` for a plain link). Coordinates and sizes are used verbatim (`src/canvas/components/CanvasRenderer.tsx`, `CanvasNode.tsx`, `CanvasEdge.tsx`; `src/canvas/utils/geometry.ts`; `src/canvas/styles/canvas.css`). |
| Canvas viewport fidelity | supported | Pan from anywhere (cards included) in the viewer, middle-button or Space+drag in the editor; one-finger touch pan and two-finger pinch zoom; multiplicative, cursor-anchored wheel zoom (0.05–5) where a horizontal scroll pans; arrow keys pan, `F` fits, `0` resets to 1:1, and browser shortcuts with Ctrl/⌘/Alt are left alone. Space is claimed only while the pointer is over a board or focus is in it. A board embedded in a page zooms only with Ctrl/⌘+wheel, a pinch, or once focused, so the page keeps scrolling. The `.canvas` format carries no viewport, so the last pan/zoom is kept in `localStorage` per board (by vault path) and adopted after hydration, so the server markup always matches; a first visit fits the board (`src/canvas/hooks/usePanZoom.ts`; `src/canvas/components/CanvasRenderer.tsx`). |
| Canvas text cards | partial | Rendered by the canvas feature's own Markdown renderer (marked extensions, so every value is escaped for its own context: link text, image alt text and attributes cannot break out). Links and embeds resolve at build time with the Markdown plugin's resolver — shortest path, vault-absolute and board-relative, case-insensitive — and `![[Note]]` transcludes any published note, sliced by `src/shared/transclusion.ts` for `#Heading`/`#^block`. Callouts (custom and foldable types), tags, footnotes (one numbering for `[^1]` and `^[…]`), highlights, attribute-less raw HTML and Mermaid fences render. Math is typeset with KaTeX loaded on demand; `mathEngine: "mathjax"` applies to note pages only, so MathJax-only TeX errors in a card. A `` ```dataview `` fence is a plain code block, because queries need the build-time page index the browser bundle cannot receive (`src/canvas/utils/markdown.ts`; `src/canvas/utils/math-render.ts`; `src/canvas/index.ts`). |
| Canvas file cards | supported | A note card shows the note (frontmatter stripped) with its name above, linking to its page; a `publish: false` or missing note shows a "not available" card and its text is never published. Images are drawn bare like Obsidian; audio and video get players; PDFs open in an unsandboxed frame (Chromium's viewer refuses a sandbox); another `.canvas` links to its board page; any other file gets a download link. Attachments are published as files at the Markdown plugin's `<prefix>/<vault path>` URL and referenced by URL, never inlined (`src/canvas/index.ts`; `src/canvas/components/CanvasNode.tsx`). |
| Canvas node subpaths | supported | `#Heading`, nested `#Parent#Child` and `#^block` (including a block id on its own line after a list) resolve for file cards and for `![[Note#Heading]]` in text cards through one node-free slicer (`src/shared/transclusion.ts`), so headings after a fence containing `# comment` and multi-line paragraphs behave as on a note page. A subpath the note does not contain shows the whole note with a notice, and the card links to the note itself (`src/canvas/index.ts`; `src/canvas/components/CanvasNode.tsx`). |
| Canvas groups | supported | Membership is derived geometrically because the format has no parent field: dragging a group moves its members as one undo step (membership is computed once per drag), and collapsing a group hides its members and their inner edges as view-only state that resets on reload; the toggle reports `aria-expanded` correctly (`src/canvas/utils/group.ts`; `src/canvas/components/CanvasRenderer.tsx`). |
| Canvas editing | partial | Opt-in via `editable`: drag, resize, add (at the view centre) and delete nodes, draw edges (attached on facing sides), Shift-click multi-select, arrow-key nudging, undo/redo that restores the original stacking order, and inline text editing (Escape commits; an unchanged edit records nothing). Changes live in browser state only — nothing is written back to the `.canvas` file; Ctrl/Cmd+S (editor only) downloads a lossless `.canvas` named after the board. Edit file/link targets, edge sides/labels and group backgrounds in Obsidian; the editor only edits text (`src/canvas/components/CanvasRenderer.tsx`). |
| Canvas as a page | supported | Every `.canvas` in the vault is published as its own route. The page carries only the board's name; the viewer fetches the one published JSON copy. Board JSON and attachments go to a plugin-owned directory (`outDir`) served as an extra public directory and emptied every build, so deleted boards and files stop being published and nothing is written to `docs/public/` (`src/canvas/index.ts`). |
| Canvas in-page embed `<CanvasEmbed src="X.canvas" />` | supported | Registered as a global MDX component; it fetches the build-time JSON from `<base>__canvases__/` at runtime, honouring the site `base` (`src/canvas/components/CanvasEmbed.tsx`; `docs/canvas/guide/embed.mdx`). |
| Canvas via `![[Board.canvas]]` | supported | Both forms need the canvas feature to be publishing that board; resolution works from docs pages as well as vault pages, through a shared route registry rather than the current page's index. `[[Board.canvas]]` links to the board's viewer route rather than the raw JSON attachment (a `#heading` subpath is dropped — a `.canvas` has no headings), and `![[Board.canvas]]` renders the same `<CanvasEmbed>` the docs use, passing the Markdown plugin's `vaultRoutePrefix` as the file-card prefix. Inside a transcluded note, or with `enableMediaEmbeds` off, the embed degrades to a styled link to the board; a board the canvas scan skipped keeps the plain attachment link (`src/markdown/resolve-wikilink.ts`, `resolveAgainstAsset`; `src/markdown/remark-wikilink.ts`, `renderEmbed`; `src/shared/canvas-routes.ts`). |
| Graph view | supported | Both scopes, switched in the settings drawer: **local** (the default) draws the current page and its neighborhood — direct neighbors at depth 1 through five hops at the maximum — and **global** draws the whole site with the current page highlighted (on a page outside the graph, the global graph still draws and nothing is highlighted). An orphan current page shows as a single node, as in Obsidian. The current route is percent-decoded and NFC-folded before matching, so pages whose names have spaces or non-ASCII characters get their graph. Renders are capped for usability (250 local neighbors, 1000 global nodes) and the footer reports anything left undrawn (`src/graph/runtime/deriveGraphViewData.ts`, `GraphPanel.tsx`). |

## How to check your own vault

The plugin's link diagnostics are the check, and the default is strict.

1. Point `vaultRoot` at your vault in `rspress.config.ts` and leave `onBrokenLink` unset. Its default is `"error"` (`src/markdown/index.ts`).
2. Run `bun run docs:build`. Every `[[…]]`, `[…](note.md)` or `obsidian://open` that resolves to nothing is reported with its reason and the page that contains it, and the build fails: failures are deferred to the end of the remark pass so one bad link does not abort the rest of the document, and then the file is failed (`src/markdown/remark-wikilink.ts`). An ambiguous target (one name, several files) resolves the way Obsidian picks and is reported as a warning through `onAmbiguousLink` (default `"warn"`; set `"error"` to fail on it). `onDataviewError` (default `"error"`) fails the build for a Dataview block that will not evaluate.
3. A fence from a plugin the site has not enabled (`tasks`, `base`, `excalidraw`, `dataview`) stays code and is only a warning by default (`onUnsupportedBlock` is `"warn"`); the warning names the option that turns it on. Errors inside an enabled plugin's block — a query that does not parse, a malformed base, a template command that fails — fail the build by default (`onPluginError` is `"error"`) and are also shown in place.
4. To publish anyway, downgrade the gates — `onBrokenLink: "warn"`. That is exactly what this repository's own demo config does (`rspress.config.ts`), which is why the docs site builds with broken demo links present.

Because the same index powers backlinks, tag pages and Dataview lookups, a build that fails on a link is also telling you that those targets are missing from the index.
