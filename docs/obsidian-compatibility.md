# Obsidian compatibility

This plugin publishes a **subset** of an Obsidian vault as an Rspress site. It reads vault files — Markdown notes, attachments, `.canvas` boards — and rewrites the Obsidian Markdown dialect into HTML at build time. It is not an Obsidian implementation and makes no attempt to reach parity: there is no plugin API, no `.obsidian/` configuration (themes, CSS snippets, workspaces), and no live preview or in-browser editing of vault files. Anything that depends on Obsidian's editor, its plugin runtime, or its sync service is out of scope, and the tables below say so rather than implying support.

Every row is grounded in the source file named in its caveat. Where a row is `partial`, the caveat names the concrete limitation.

| Status | Meaning |
| --- | --- |
| supported | Implemented, with the caveat noted where one exists |
| partial | Implemented for a subset, or with a known limitation named in the caveat |
| not supported | Not implemented |

Feature toggles decide most of this surface: wikilinks, comments, highlights, footnotes and block anchors are always on; Markdown links and case-insensitive lookup default to `true`; everything else (callouts, transclusion, media embeds, tag links, tag pages, backlinks, Dataview, daily notes, math, Mermaid) is opt-in. See `src/markdown/index.ts` (`normalizePluginOptions`) for the defaults.

## Markdown dialect

| Feature | Status | Caveat |
| --- | --- | --- |
| Wikilinks `[[Page]]`, `[[Page\|Alias]]` | supported | Always on. Targets may be vault-relative, note-relative (`./`, `../`), a bare basename, a frontmatter title or an alias — see `src/markdown/resolve-wikilink.ts` (`resolveWikiLink`). |
| Heading and block anchors `[[Page#Heading]]`, `[[Page#^id]]`, `[[#Heading]]` | supported | Heading lookup tries an explicit `{#id}`, the slug, raw text, an emoji prefix and a case-insensitive substring in that order (`src/markdown/resolve-wikilink.ts`, `resolveHeadingSlug`). Block ids are compared case-insensitively after whitespace normalization (`resolveBlockId`). |
| Vault search `[[##query]]`, `[[^^query]]` | supported | Resolved while compiling against every page's headings (`##`) or block ids (`^^`). A query matching exactly one target becomes a normal link; a query matching several renders an inline `<WikiPicker>` — a button that opens a filterable list of the matches, the way Obsidian offers a picker instead of refusing the link. The candidates are resolved at build time and travel in the component's attributes, so the picker works on a static export with no runtime data module; a query matching nothing stays an unresolved-link marker (`src/markdown/resolve-wikilink.ts`, `resolveVaultSearch`; `src/markdown/runtime/WikiPicker.tsx`). |
| Escapes inside wikilinks (`\|`, `\#`, `\^`, `\[`, `\]`) | supported | Those five characters only; the tokenizer is scanner-based, so an escaped `]` never closes the link (`src/markdown/parse-wikilink.ts`). |
| Unresolvable links | supported | A dimmed span keeps the readable label, with the raw `[[…]]` syntax and the reason in its attributes (`src/markdown/remark-wikilink.ts`, `createUnresolvedNode`). |
| Ambiguous links | supported | `onAmbiguousLink` defaults to `"error"`; several pages matching one target fails the build (`src/markdown/index.ts`). |
| Note embeds `![[Page]]` and transclusion | supported | Opt-in via `enableTransclusion`. The embedded file is re-run through the same pipeline, so headings, callouts and tags inside it render normally (`src/markdown/remark-wikilink.ts`, `renderPageEmbed`). |
| Transclusion subpaths `![[Page#Heading]]`, `![[Page#^id]]` | supported | Sections are sliced from the raw source: a heading runs to the next heading of equal or higher level, ignoring frontmatter and fenced code; a block id takes the paragraph above a standalone `^id` or the line carrying a trailing ` ^id` (`src/markdown/remark-wikilink.ts`, `extractHeadingSection`). |
| Transclusion depth and cycles | supported | Depth is capped at 5 and a circular embed is refused; both leave the raw embed as text plus a diagnostic (`src/markdown/remark-wikilink.ts`, `MAX_TRANSCLUSION_DEPTH`). |
| Media embeds | supported | Every format in Obsidian's accepted list, from one shared table both renderers read (`src/shared/media-exts.ts`): images `avif`, `bmp`, `gif`, `jpeg`, `jpg`, `png`, `svg`, `webp`; audio `3gp`, `flac`, `m4a`, `mp3`, `ogg`, `wav`; video `mkv`, `mov`, `mp4`, `ogv`, `webm`; and `pdf`. Sizing follows Obsidian in both forms — a numeric pipe on a wikilink embed (`![[img.png\|300]]`, `\|300x200`) and the same syntax on a markdown image (`![300](img.png)`, `![300x200](img.png)`, `![A caption\|300](img.png)`). A PDF takes `#page=N` in the frame's `src` (so the browser opens that page, and the caption bar says which page) and `#height=N` as the frame height, in a `figure` with a caption bar naming the file and an "Open" link to it. A file missing from disk still emits a root-relative `src` and warns, so a link that starts working once the file lands needs no rewrite; whether a given browser can decode a format is the same codec question it is in Obsidian. `.webm` is rendered as video — Obsidian lists it under both audio and video — and an audio-only `.webm` still plays through the video element (`src/markdown/remark-wikilink.ts`, `src/canvas/utils/markdown.ts`). |
| Callouts | supported | Opt-in via `enableCallouts`. Aliases normalise (`summary`/`tldr` → `abstract`, `check`/`done` → `success`, `help`/`faq` → `question`, `hint`/`important` → `tip`, `attention` → `caution`, `fail`/`missing` → `failure`, `error` → `danger`, `cite` → `quote`), `+`/`-` produce `<details open>`/`<details>`, nesting is resolved innermost-first, and callouts already claimed by Rspress's GitHub-alert transform are restored from source first (`src/markdown/remark-wikilink.ts`, `CALLOUT_TYPE_ALIASES`, `processCallouts`). |
| Unknown callout types | supported | A type outside the alias table keeps its own `callout-<type>` class and Obsidian's `data-callout` attribute, and falls back to Obsidian's `note` styling (blue card, pencil glyph) instead of a neutral placeholder. `todo` has its own blue card and checkbox glyph, and every bundled type ships a colour and a title glyph; restyle any type with the CSS variables Obsidian documents (`src/markdown/styles.css`; glyphs generated by `scripts/generate-icons.ts`). |
| Callout titles | supported | Title text is inline Markdown: wikilinks resolve, `==highlight==` becomes `<mark>`, and a code span in the title disables highlight splitting (`src/markdown/remark-wikilink.ts`, `renderCalloutTitleHtml`). |
| Tags | supported | Inline `#tag` (at least one non-numeric character required) and frontmatter `tags`/`tag`, merged per page. `enableTagLinking` rewrites inline tags into links to `/tags/<tag>`, which only exist when `enableTagPages` is also on; `a/b/c` also aggregates `a` and `a/b` (`src/markdown/content-index.ts`, `extractInlineTags`; `src/markdown/tag-pages.ts`, `generateTagPages`). |
| Comments `%%…%%` | supported | Whole nodes between the delimiters are removed, including paragraphs and headings. Delimiters inside frontmatter, fenced code and inline code are ignored; an unclosed `%%` stays as written. Code spans pair the CommonMark way across a paragraph: an opener hides delimiters only up to the next run of the same length, and an unpaired run is literal text that silences nothing (`src/markdown/comments.ts`). |
| Commented-out headings | supported | The heading is removed from the body, the page outline and the search index. Rspress builds the outline and the index from its own parse of the source, before plugin remark plugins run, so the plugin drops the matching entries afterwards: by the `charIndex` Rspress records, or — when `search: false` leaves no offsets — by heading identity, reconciled against the live headings so a same-named live heading keeps its entry (`src/markdown/comments.ts`, `filterCommentedToc`; `modifySearchIndexData` and `extendPageData` in `src/markdown/index.ts`). |
| Highlights `==text==` | supported | Rendered as `<mark>`. A single `=` may appear inside the span (`==key=value==`); a bare run like `====` is left alone (`src/markdown/remark-wikilink.ts`, `HIGHLIGHT_PATTERN`). |
| Footnotes `[^id]`, `[^id]: …`, `^[inline]` | supported | Definitions are collected before references, so a reference can precede its definition; each reference carries the plain-text definition as its `title`. The footnotes block renders each definition — label-based and inline — as inline Markdown with resolved wikilinks (bold, code, links, `==highlights==`), through the same renderer as callout titles, plus the back-reference arrow (`src/markdown/remark-wikilink.ts`, `renderAllFootnotesHtml`). An inline `^[…]` is found at the phrasing level and matched by bracket depth, so its content may contain Markdown, wikilinks and brackets of its own; an unclosed `^[` stays literal text (`src/markdown/inline-footnotes.ts`). Canvas text cards render both forms too (`src/canvas/utils/markdown.ts`). |
| Math `$…$`, `$$…$$` | supported | Two engines, chosen with `mathEngine`. `katex` (the default, and a dependency) renders inline and display math during the build, with the mhchem contrib registered so `\ce{H2O}` and `\pu{…}` work. `mathjax` selects Obsidian's own engine for the TeX KaTeX does not implement: it is an optional dependency (`bun add mathjax-full`), loaded once per build, and its generated CommonHTML stylesheet is emitted inline with the page. Malformed TeX renders as the engine's own inline error rather than failing the build. Inline math may not begin or end with a space and may not contain a newline, so `$5 and $10` stays prose — Obsidian's own rule (`src/math.ts`, `prepareMathEngine`; `src/markdown/remark-wikilink.ts`, `MATH_PATTERN`). Opt-in via `enableMath`; code fences and inline code are untouched. |
| Mermaid | supported | Opt-in via `enableMermaid`. Rendered in the browser, with mermaid's `securityLevel` configurable through `mermaidSecurityLevel` — `"strict"` (the default) runs mermaid's own sanitising pass and strips unsafe link URLs, so a `click` directive with a `javascript:` URL is removed rather than rendered as a live anchor; the looser levels allow what a strict build refuses. The level travels with each placeholder and configures the shared client instance. A failed or timed-out (10s) render keeps the raw source, marks the block as an error and logs a console warning (`src/mermaid/blocks.ts`). |
| Frontmatter / properties | supported | YAML and JSON, the two formats Obsidian's own Properties read; a document is matched on its frontmatter, not its extension. A `---js` marker is refused by a throwing engine stub rather than executed, and any other language marker is rejected before the parser runs — executing frontmatter is a Dataview feature, not Obsidian's, and the plugin interprets DataviewJS in a restricted interpreter instead. A refused or malformed block publishes the page with empty metadata and a console warning, so one bad header cannot fail a build. Keys read: `title`, `aliases`/`alias`, `tags`/`tag`, `cssclasses`/`cssclass`, `excerpt`, `publish` (`src/shared/frontmatter.ts`; `src/markdown/content-index.ts`). |
| `excerpt` | supported | Copied into the page description through Rspress's `extendPageData` hook, so the theme renders it as `<meta name="description">` and `og:description`. An explicit frontmatter `description` wins; without one, the excerpt overrides the auto-extracted first paragraph, and whitespace inside the excerpt is collapsed (`src/markdown/index.ts`). |
| `publish: false` | supported | Keeps a page out of the site wherever it lives. A **vault** page is dropped from the content index, so it is never routed or linkable. A **docs-root** page has its route removed from Rspress's route service, which takes the page out of the build, out of the auto-generated sidebar and nav (both derived from the routes) and out of the search index (built from the same route service). A page an explicit sidebar or nav config still lists keeps its entry there, so remove it from the config too (`src/markdown/content-index.ts`; `src/markdown/index.ts`, `routeServiceGenerated`). |
| Arbitrary frontmatter keys | supported | Copied into the page's Dataview fields twice — verbatim and sanitized (lowercased, spaces to dashes) — so `My Key` and `my-key` both resolve (`src/markdown/dataview.ts`, `extractDataviewMetadata`). |
| Markdown links into the vault `[label](note.md)` | supported | On by default (`enableMarkdownLinks`). Only `.md`/`.mdx` destinations are claimed; external URLs, pure anchors and extensionless routes are left to Rspress, and unresolvable destinations are reported through `onBrokenLink` (`src/markdown/remark-wikilink.ts`, `processMarkdownLinks`). |
| Reference-style links `[label][ref]` | supported | The `[ref]: Page.md` definition is rewritten, which fixes every reference to it at once (`src/markdown/remark-wikilink.ts`, the `definition` visitor in `processMarkdownLinks`). |
| Markdown embeds `![alt](note.md)` | supported | Inlined when `enableTransclusion` is on, otherwise rendered as a styled embed link (`src/markdown/remark-wikilink.ts`, `processMarkdownEmbeds`). |
| Block IDs | supported | A standalone `^id` line and a trailing ` ^id` are indexed, and anchors are emitted on the page for the ids the index knows, so `[[page#^id]]` and block searches resolve (`src/markdown/content-index.ts`; `src/markdown/remark-wikilink.ts`, `emitBlockAnchors`). |
| Headings and aliases as link targets | supported | GitHub-slugger slugs plus explicit `{#custom-id}` are indexed (explicit ids win), and frontmatter aliases are matched after exact path and basename lookups (`src/markdown/content-index.ts`; `src/markdown/resolve-wikilink.ts`, `resolveHeadingSlug`). |
| `obsidian://` links | partial | Only `obsidian://open` resolves — `file` (or legacy `path`) with an optional `#Heading`, `%23Heading` or `subpath` parameter — and the `vault` parameter is ignored because one site publishes one vault. `search`, `new`, `hook-get-address` and any unparseable URI are left as written and reported through `onBrokenLink` (`src/markdown/remark-wikilink.ts`, `parseObsidianUriTarget`). |
| Standard Markdown and GFM | supported | Tables, task lists and the rest come from Rspress's own Markdown pipeline; this plugin is a remark pass layered on top of it (`src/markdown/index.ts`). |

## Vault formats, canvas and graph

| Feature | Status | Caveat |
| --- | --- | --- |
| `.canvas` parsing | supported | JSON Canvas `text`/`file`/`link`/`group` nodes, edges with sides/ends/labels/colours, `assets` and `notes` are read. A malformed **card** is dropped rather than failing the board — one hand-edited node no longer costs every other card on it — and each drop is reported by name and reason on the console, so nothing is lost silently; a duplicate id keeps the first, and an edge whose endpoint was dropped goes with it. Only a structurally broken document (unparseable JSON, `nodes` not an array, a malformed `assets`/`notes` map) is a hard error, and then the raw board is still published (`src/canvas/parser.ts`, `parseCanvas`; `src/canvas/index.ts`). |
| Canvas rendering | supported | Pan/zoom clamped to 0.1–5, fit-on-mount, node colours (presets 1–6 or CSS colours), edge sides/arrows/labels, group backgrounds. Files are rendered as they are stored, so coordinates and sizes are used verbatim (`src/canvas/components/CanvasRenderer.tsx`; `src/canvas/utils/color.ts`). |
| Canvas viewport fidelity | supported | The `.canvas` format carries no viewport — Obsidian keeps it in its own workspace state rather than in the board — so the viewer restores the last pan/zoom from `localStorage`, keyed by the route the board is published at, and skips its one-off fit when it has one to restore. A first visit still frames the node bounds, a stored value that is not a usable viewport (or a zoom outside the viewer's own range) is ignored, and **Fit to View** resets the position on demand (`src/canvas/hooks/usePanZoom.ts`, `src/canvas/components/CanvasRenderer.tsx`). 
| Canvas text cards | partial | Rendered by the canvas feature's own Markdown renderer rather than the Markdown plugin's remark pipeline, so wikilinks, note embeds, callouts, tags, math, footnotes, highlights and Mermaid fences all render inside a card — each with the same rules the Markdown plugin uses, including the `====` highlight exemption. What does not carry over is anything that needs the build-time page index: a `` ```dataview `` fence in a card is a plain code block, and `enableDataview` has no effect there, because a `ContentPage` carries Maps, Dates and an index that the browser bundle cannot receive (`src/canvas/utils/markdown.ts`). |
| Canvas file cards | supported | A card pointing at a note inlines that note's content (frontmatter stripped) at build time; images/audio/video/PDF become data URLs, and an extension outside the MIME table degrades to a filename card (`src/canvas/index.ts`; `src/canvas/components/CanvasNode.tsx`). |
| Canvas node subpaths | supported | `#heading`/`#^block` resolves for **file** cards, and a `![[Note#Heading]]` written inside a text card now inlines just that section instead of the whole note. Both paths call one node-free slicer (`src/shared/transclusion.ts`), so a card and a note page cannot drift; a subpath the note does not contain falls back to the whole note rather than an empty card (`src/canvas/index.ts`; `src/canvas/utils/markdown.ts`; `src/shared/transclusion.ts`). |
| Canvas groups | supported | Membership is derived geometrically on every render because the format has no parent field: groups paint behind their members, dragging a group moves its members as one undo step, and collapsing a group hides its members and their edges as view-only state that resets on reload (`src/canvas/utils/group.ts`; `src/canvas/components/CanvasRenderer.tsx`). |
| Canvas editing | partial | Opt-in via `editable`: drag, resize, add and delete nodes, draw edges, undo/redo and inline text editing all work, but only in browser state — nothing is written back to the `.canvas` file, and Ctrl/Cmd+S downloads a `.canvas` blob. The banner says it plainly: "Read-only source until exported" (`src/canvas/components/CanvasRenderer.tsx`, `exportCanvas`). |
| Canvas as a page | supported | Every `.canvas` in the vault is published as its own route, and its enriched JSON is written next to the site so the embed component can fetch it (`src/canvas/index.ts`). |
| Canvas in-page embed `<CanvasEmbed src="X.canvas" />` | supported | Registered as a global MDX component; it fetches the build-time JSON from `__canvases__/` at runtime (`src/canvas/components/CanvasEmbed.tsx`; `docs/canvas/guide/embed.mdx`). |
| Canvas via `![[Board.canvas]]` | supported | Both forms need the canvas feature to be publishing that board; resolution works from docs pages as well as vault pages, through a shared route registry rather than the current page's index. `[[Board.canvas]]` links to the board's viewer route rather than the raw JSON attachment (a `#heading` subpath is dropped — a `.canvas` has no headings), and `![[Board.canvas]]` renders the same `<CanvasEmbed>` the docs use, passing the Markdown plugin's `vaultRoutePrefix` as the file-card prefix. Inside a transcluded note, or with `enableMediaEmbeds` off, the embed degrades to a styled link to the board; a board the canvas scan skipped keeps the plain attachment link (`src/markdown/resolve-wikilink.ts`, `resolveAgainstAsset`; `src/markdown/remark-wikilink.ts`, `processEmbedsInTree`; `src/shared/canvas-routes.ts`). |
| Graph view | supported | Both scopes, switched in the filter bar: **local** (the default) draws the current page and its neighborhood — direct neighbors at depth 1 through five hops at the maximum — and **global** draws every published page with the current one highlighted, the way Obsidian's global graph does. Search (`path:`, `file:`, `tag:`, text, `-` negation, quotes, AND), tag and orphan toggles, and per-visitor persistence in `localStorage` apply to both; the depth control steps aside in the global scope. Renders are capped for usability (250 local neighbors, 1000 global nodes) and the footer reports anything left undrawn (`src/graph/runtime/deriveGraphViewData.ts`, `GraphPanel.tsx`). |
| Graph edges | supported | Wikilinks, Markdown links and `#tags` (only where tag routes exist) become edges; fenced and inline code are masked out, self-links and duplicate pairs are dropped, and an unresolved target is reported per `onUnresolvedLink` — `"warn"` by default, `"error"` to fail the build, `"ignore"` for a site that already hears about them from the markdown plugin (`src/graph/build/link-extractor.ts`; `src/graph/build/graph-builder.ts`). |
| Graph filters, search, colour groups | supported | The panel's filter bar has a search box (the query language: plain text, `path:`, `file:`, `tag:`, `-` negation, quoted phrases, ANDed together), a neighborhood-depth stepper (1–5, default 1) and Tags and Orphans toggles; depth and toggles persist per visitor in `localStorage`, the search text does not, and **Escape** clears a non-empty search before closing the panel. Colour groups come from the plugin's `groups` option — the same query language, first match wins, the current page keeps its colour and invalid colours fall back to the palette. There is deliberately no attachments toggle, because attachment nodes do not exist (nodes are published pages only), and no global-graph filtering: filters only ever shape the local graph (`src/graph/runtime/GraphPanel.tsx`; `src/graph/runtime/deriveGraphViewData.ts`; `src/graph/runtime/graph-query.ts`; `src/graph/runtime/graph-panel-storage.ts`; `src/graph/index.ts`, `groups`). |
| Backlinks | supported | Built from `[[wikilinks]]` — embeds included, since an embed **is** a backlink in Obsidian's own Backlinks pane (its 0.8.11 changelog restored exactly that) — and from Markdown links and reference-style definitions whose path ends in `.md`/`.mdx`, with or without a `#heading` or `?query` suffix. That is the same set the graph extractor counts, so the two no longer disagree. Fenced code, inline code, comments and frontmatter are excluded, as are a `^`-prefixed footnote or `~`-prefixed citation definition and a **media or PDF** target — an image, audio, video or `.pdf` (`src/shared/media-exts.ts`) — because such a target names a file rather than a page. Those are kept out of Dataview's `file.outlinks` too, so they cannot render a link to a route the site never publishes; a link to any other non-Markdown file, such as `[[data.json]]`, is still a backlink and still resolves as an asset. Two forms remain out, and both match Obsidian rather than fall short of it: an `obsidian://open` URI, which Obsidian does not index as a note link at all, and an **extensionless** destination such as `[text](Note)`, which the graph already counts but the Backlinks panel does not yet (`src/markdown/content-index.ts`, `extractWikilinkTargets`; `src/markdown/backlinks.ts`, `renderBacklinksHtml`). |
| Unlinked mentions | supported | `enableUnlinkedMentions` renders Obsidian's second backlinks list — pages that *name* this page without linking to it — each with a snippet of the surrounding text. A page's names are its frontmatter `title`, its `aliases` and its file name, so a heading is not a name; a name claimed by several pages is skipped rather than guessed, matching how an ambiguous link target is treated. Pages that also link here are listed as backlinks, never twice, and the feature keeps a capped (≈20k character) stripped copy of each page body while it is on, which is why it is off by default (`src/markdown/mentions.ts`; `src/markdown/content-index.ts`, `unlinkedMentions`). |
| Attachments | supported | Every non-`.md`/`.mdx` vault file is indexed as an asset and copied under `public/<vaultRoutePrefix>/…`, so embeds and links share one URL scheme (`src/markdown/content-index.ts`; `src/markdown/index.ts`, `copyVaultAssets`). |
| Cache invalidation | supported | The content index and the transclusion memo are dropped at the start of every dev recompile and production build, so an edit to an embedded page shows up without a restart (`src/markdown/index.ts`). |

## Plugin ecosystem

| Feature | Status | Caveat |
| --- | --- | --- |
| Dataview DQL | supported | `TABLE` (with `WITHOUT ID`), `LIST`, `TASK` and `CALENDAR`; `FROM` accepts `"folder"`, `"folder/File.md"`, `#tag`, `[[note]]`, `inlinks([[note]])` and `outlinks([[note]])` combined with `AND`/`OR`/`-`/parentheses; `WHERE`, `SORT`, `GROUP BY` (several keys, one row per combination), `THEN` (a per-group aggregate), `FLATTEN` and `LIMIT` (a literal or an expression) are supported. `CALENDAR` renders a month grid per month in the results, newest first, filing rows under `file.day` and falling back to the note's creation day. Functions: `date`, `now`, `today`, `year`, `month`, `weekday`, `weeknumber`, `weekyear`, `hour`, `minute`, `second`, `striptime`, `dateformat`/`formatdate`, `dateplus`/`dateminus`, `length`, `contains`, `startswith`, `endswith`, `lower`, `upper`, `trim`, `truncate`, `padleft`, `padright`, `titlecase`, `capitalize`, `reversestring`, `regexmatch`, `replace`, `split`, `join`, `typeof`, `default`, `choice`, `nonnull`, `defaultblank`, `sum`, `average`, `min`, `max`, `firstvalueof`, `lastvalueof`, `distinct`, `flatten`, `any`, `all`, `strictsort`, `round`, `floor`, `ceil`; bracket indexing (`rows[0]`, `scores[-1]`, `file["name"]`) is supported and reads past the end as empty. A function outside this set throws rather than guessing. Off by default (`enableDataview`), and failures follow `onDataviewError` (default `"error"`, which fails the build) (`src/markdown/dataview.ts`; `src/markdown/remark-wikilink.ts`, `reportDataviewDiagnostic`). |
| Dataview inline expressions | partial | Only a bare `= name` or `= fn(…)` preceded by whitespace, `(` or the start of the text is evaluated, and only while `enableDataview` is on; `(key:: value)` fields are unwrapped to the bare value. An expression resolving to nothing is left exactly as written rather than collapsed into an empty span, so prose containing `= word` survives untouched, and only an expression that genuinely throws is reported through `onDataviewError` (`src/markdown/remark-wikilink.ts`, `processDataviewNodes`; `src/markdown/dataview.ts`, `renderDataviewInline`). |
| Dataview implicit fields | supported | `file.path/name/folder/ext/size/link/tags/etags/outlinks/inlinks/tasks/lists`, plus `ctime`, `mtime`, `cday`, `mday` and `day` (daily notes only) (`src/markdown/dataview.ts`, `createPageValues`). |
| DataviewJS | partial | Never evaluated as JavaScript. A restricted interpreter handles `const`/`let`/`var x = …` statements, `dv.table`/`list`/`taskList`/`paragraph`/`header`, `dv.pages`/`current`/`page`/`array`/`date`, collection `where`/`filter`/`map`/`sort`/`limit`/`slice`/`join`/`flat` and single-expression arrow callbacks. Source text matching a forbidden-API regex (`process`, `fetch`, `eval`, `window`, `require`, …) is rejected outright, and any other statement, function or method errors (`src/markdown/dataview-js.ts`). |
| Daily notes | supported | Off by default (`enableDailyNotes`). Filenames are matched against a configured `folder` and `dateFormat` (tokens `YYYY`, `YY`, `MMMM`, `MMM`, `MM`, `M`, `DD`, `D`, `dddd`, `ddd`) and must round-trip to a real date; `{{date}}`, `{{date:FORMAT}}`, `{{date±Nd/w/m/y}}`, `{{title}}` and `{{time}}` expand, and previous/current/next links are injected over the adjacent published daily notes. A note whose body is still empty is filled from `dailyNotes.template` (a note already being written is never touched), and `dailyNotes.calendar` generates a page listing every daily note by month, newest first (`src/markdown/daily-notes.ts`). |
| Tags | supported | Frontmatter `tags`/`tag` plus inline `#tag` feed generated `/tags/{name}` pages, with nested-tag ancestors created for you (`src/markdown/tag-pages.ts`). |
| Tasks plugin | not supported | List-item checkboxes are indexed (so `TASK` queries and `file.tasks` work), but a `` ```tasks `` query block is not executed — it is rendered as code with a warning (`onUnsupportedBlock`, default `"warn"`) (`src/markdown/remark-wikilink.ts`, `UNSUPPORTED_PLUGIN_FENCES`). |
| Excalidraw | not supported | Only the `` ```excalidraw `` fence is recognised, and only so it can be reported; `.excalidraw` files are never read (`src/markdown/remark-wikilink.ts`, `UNSUPPORTED_PLUGIN_FENCES`). |
| Bases | not supported | The `` ```base `` fence is reported and left as code; `.base` files are never indexed (`src/markdown/remark-wikilink.ts`, `UNSUPPORTED_PLUGIN_FENCES`). |
| Kanban | not supported | A `` ```kanban `` fence is published as an ordinary code block, reported through the shared unsupported-fence diagnostic (`onUnsupportedBlock`, default `"warn"`) exactly like the Tasks, Excalidraw and Bases fences; board layouts are never rendered and `.canvas`-style board data is not read (`src/markdown/remark-wikilink.ts`, `UNSUPPORTED_PLUGIN_FENCES`). |
| Templater | not supported | No `<% … %>` handling in `src/`; the Markdown guide names Templater as out of scope. |

## Obsidian app features

| Feature | Status | Caveat |
| --- | --- | --- |
| Themes (`.obsidian/themes`) | not supported | The vault scanner skips every dot-directory, so theme files are never read; the site is styled by Rspress plus the plugin's own stylesheets (`src/markdown/content-index.ts`). |
| CSS snippets (`.obsidian/snippets`) | not supported | Nothing reads a snippet directory. The closest equivalent is frontmatter `cssclasses`, which wraps the rendered page body in your classes (`src/markdown/remark-wikilink.ts`). |
| `.obsidian/` configuration | not supported | Skipped by both the index scanner and the bundled sync helper, so appearance, graph and core-plugin settings are never read (`src/markdown/content-index.ts`; `scripts/obsidian-sync.ts`). |
| Community plugin API | not supported | No Obsidian plugin code is loaded, and there is no `app`/`Plugin`/`workspace` surface. DataviewJS is interpreted rather than evaluated and is rejected when its source mentions host APIs (`src/markdown/dataview-js.ts`). |
| Workspaces and pane layout | not supported | `.obsidian/workspace.json` is excluded from the index and from the sync helper; the published site is one page per route (`scripts/obsidian-sync.ts`). |
| Obsidian Sync | not supported | There is no sync client. The repo's `bun run obsidian:sync` is a one-way vault → docs file copier with its own manifest, not Obsidian Sync (`scripts/obsidian-sync.ts`). |
| Live preview and live editing | not supported | Publishing is a build-time transform. The canvas editor is the only in-browser editor and it never saves (`docs/markdown/guide/link-resolution.md`; `src/canvas/components/CanvasRenderer.tsx`). |
| Mobile app | not supported | The output is a static site assembled by `pluginObsidian`, which returns Rspress plugins — not an Obsidian-compatible app or plugin bundle (`src/index.ts`). |
| PDF export | not supported | No export pipeline exists for pages or canvases. PDFs appear only as embedded attachments via an `<iframe>` in a media embed, or as a canvas file card (`src/markdown/remark-wikilink.ts`, the PDF branch of media embeds). |

## How to check your own vault

The plugin's link diagnostics are the check, and the default is strict.

1. Point `vaultRoot` at your vault in `rspress.config.ts` and leave `onBrokenLink` unset. Its default is `"error"` (`src/markdown/index.ts`).
2. Run `bun run docs:build`. Every `[[…]]`, `[…](note.md)` or `obsidian://open` that resolves to nothing is reported with its reason and the page that contains it, and the build fails: failures are deferred to the end of the remark pass so one bad link does not abort the rest of the document, and then the file is failed (`src/markdown/remark-wikilink.ts`). The same applies to `onAmbiguousLink` (default `"error"`) when one target matches several pages, and to `onDataviewError` (default `"error"`) for a Dataview block that will not evaluate.
3. Unsupported plugin fences are only warnings by default (`onUnsupportedBlock` is `"warn"`), so a vault full of `tasks`/`excalidraw`/`base`/`kanban` fences will build while telling you on the console that those blocks stay as code.
4. To publish anyway, downgrade the gates — `onBrokenLink: "warn"`. That is exactly what this repository's own demo config does (`rspress.config.ts`), which is why the docs site builds with broken demo links present.

Because the same index powers backlinks, tag pages and Dataview lookups, a build that fails on a link is also telling you that those targets are missing from the index.
