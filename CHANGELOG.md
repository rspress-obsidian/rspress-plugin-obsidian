# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Breaking Changes

- Renamed plugin exports: `pluginObsidianWikiLink` → `markdown`, `pluginObsidianCanvas` → `canvas`, `pluginGraphview` → `graphview` — the declarations now carry the short names throughout (not just re-export aliases)
- Nothing was ever published under this name, so these are decisions for the first release rather than changes users have to migrate: `rspress-plugin-obsidian` is the unified package name (no umbrella entry existed before)
- **The documented stylesheet import did not work.** The quick starts told people to `import stylesPath from "rspress-plugin-obsidian/markdown/styles.css?url"` and pass it to `globalStyles`. Rspress loads `rspress.config.ts` with Node, not with the bundler, so a `.css` specifier fails before the build starts — `ERR_PACKAGE_PATH_NOT_EXPORTED` with the `?url` suffix, `ERR_UNKNOWN_FILE_EXTENSION` without it. Verified against a real consumer install of the packed tarball. The quick starts now use `enableDefaultStyles: true`, which is the mechanism that works, and the three places that documented the import show the `createRequire` + `globalStyles` form for when you need control over load order
- **The Markdown feature factory is `markdown()`, not `wikilink()`.** Every other name in the package already said "markdown" — the `src/markdown/` directory, the `./markdown` export subpath, `markdown/styles.css`, the `rspress-plugin-obsidian:markdown` identity — and the factory was the single symbol that disagreed, at the exact place a consumer meets it first. It also covered 14 options (callouts, transclusion, media embeds, Dataview, daily notes, tags, tag pages, backlinks, unlinked mentions, math, Mermaid, Markdown links, fuzzy and case-insensitive lookup), which `wikilink()` advertised none of. The option type follows: `RspressPluginObsidianWikiLinkOptions` is now `RspressPluginMarkdownOptions`. "Wikilink" keeps its meaning as the `[[…]]` *syntax* — `remarkWikilink`, `findWikilinkMatches`, `wikilinkTargets` and the rest are unchanged, because they are about the token, not the feature
- Removed the unused `ContentIndex.rawContentByPath` field (it retained every note's full text and nothing read it)
- Canvas file-node links now emit the same routes the vault pages are published at (`/vault/Welcome`, not `/vault/welcome`); canvas assets remain site-root relative
- Plugin identities and console prefixes are now `rspress-plugin-obsidian:markdown`, `:canvas` and `:graph` — the pre-merge names (`rspress-plugin-obsidian-wikilink`, …) no longer appear in build warnings, `profileBuild` logs or Rspress's plugin list

### Added

- **Unlinked mentions** (`enableUnlinkedMentions`) — Obsidian's second backlinks list: pages that *name* the current page without linking to it, each with a snippet of the surrounding text. A page's names are its frontmatter `title`, its `aliases` and its file name, so a heading is not a name; a name claimed by several pages is skipped rather than guessed, matching how an ambiguous link target is treated; pages that also link here stay in the backlinks list so the two never repeat each other. It implies `enableBacklinks` (that panel is where they render) and keeps a capped, stripped copy of each page body while it is on, which is why it defaults to off
- **`obsidian://` links resolve to the page they name.** `obsidian://open?vault=…&file=Note#Heading` (and the legacy `path` form, a `subpath` parameter, `%23Heading`, and `^block` fragments) now resolves through the same ladder as every other link; `search`, `new` and `hook-get-address` cannot be served by a static site, so those and unparseable URIs are left as written and reported through `onBrokenLink` instead of shipping a dead link nothing mentions
- **`onUnsupportedBlock`** (default `"warn"`) reports Tasks, Excalidraw and Bases fences — and Dataview fences when the feature is off — once each, so plugin syntax this plugin cannot render is visible in the build output instead of silently appearing as a code block
- **Canvas groups behave like containers.** A group paints behind the nodes it holds (even when the file lists it last), dragging a group moves its members as one undo step, and a collapse control hides them along with any edge whose endpoints are both hidden. Membership is containment geometry recomputed per render, so dragging a card in or out re-parents it, and nothing new is written to the `.canvas` file
- **mhchem** is registered for KaTeX, so `\ce{H2O}` and `\pu{…}` render the way Obsidian's MathJax renders them
- **`docs/obsidian-compatibility.md`** — a per-feature coverage page (supported / partial / not supported, ~70 rows) that names the limitation and the source file on every partial row, states up front that this is a publishing subset rather than an Obsidian implementation, and ends with how to check a vault (`onBrokenLink: "error"` fails the build on any unresolvable link)
- Tests: the mentions matcher and its end-to-end path through `markdown()`, containment and z-order for canvas groups, and mhchem rendering
- **The plugin now runs on Windows, macOS and Linux, and CI proves it.** The `test` job runs typecheck, the unit suite, the build, the packed-tarball test, the coverage gate, `docs:build` and the build-integration tests on all three; e2e runs on Linux and macOS. Everything below was found by taking that claim seriously
- `.gitattributes` (`* text=auto eol=lf`, binary markers for images/PDFs/fonts) so a Windows checkout with `core.autocrlf=true` cannot rewrite LF to CRLF and fail tests against files nobody edited
- `test/markdown/windows-fixtures.test.ts`: the same vault written twice (LF and CRLF) — frontmatter tags, heading, block id, wrapped paragraph, fence, callout, comment, wikilink, transclusion, plus a CRLF `.canvas` — asserted to produce byte-identical HTML and identical indexes
- Windows-shaped lcov cases in the coverage-gate tests, NFD/NFC resolution tests through the index and the resolver, extended-length-realpath unit tests, `test/clean.test.ts`, `test/gitattributes.test.ts`, and loud counted skips for the symlink-dependent tests where the OS needs privileges to create one
- Tests for wiring that no test loaded before, which is what let the coverage gate's exemption list hide it: `src/index.test.ts` (umbrella composition and the helper surface users import), `src/graph/index.test.ts` (the factory's `routeGenerated`/`addRuntimeModules` hooks against a real temp docs root, including the virtual module's nodes, edges and cache reuse), `src/graph/runtime/GraphSidebar.test.tsx` and `src/markdown/runtime/MermaidBlocks.test.tsx`
- `routeHref` / `isIndexRoute` in `src/route-path.ts`, and an artifact-level guard in `test/markdown/integration.test.ts` that resolves every internal href in the built site against the files Rspress emitted
- `src/markdown/frontmatter.ts` — the one place frontmatter is parsed, shared by the content index and the graph extractor, with the engine allow-list and marker check that keep `---js` inert
- `src/route-path.ts` — one route derivation for the markdown index, the canvas file-node resolver and the option normalizers, node-free so the browser bundle does not inherit `node:fs`; the canvas copy and its cross-implementation drift guard are gone
- `src/escape.ts` — one HTML escaper (text and attribute variants) replacing six copies across the markdown, Dataview and canvas renderers, and the one URL-scheme allowlist (`sanitizeUrl`) every renderer emits an `href` through
- Painter-level graph tests that assert what the force-graph callbacks actually draw, a symlink-containment test, a `---js` execution test, a canvas render-cost test that counts parses per commit, and a coverage-gate test that drives the script as a subprocess
- Regression tests for the earlier round of fixes: Windows vault-root detection, daily-note parsing of weekday and month-name formats, canvas editor keystrokes and drag pointer capture (both proved to fail against the pre-fix code), and graph resolution of frontmatter titles/aliases and attachment embeds
- Coverage of the shipped canvas components (nodes, edges, renderer, pan/zoom), the Dataview query pipeline and DataviewJS interpreter, and the markdown resolver's error paths; coverage of the shipped source rose from 82.0% to 94.4% of 9,051 statements

- Coverage gates: `bunfig.toml` pins the denominator to the shipped source (`coveragePathIgnorePatterns` drops `dist/`, `doc_build/`, test helpers) and holds a per-file floor, while `scripts/check-coverage.ts` enforces the 90% repo-wide floor in CI (Bun's threshold is per file, so it cannot express a total)
- `graph/runtime/canvas/` is now `graph/runtime/palette/`. Nothing in it is Obsidian canvas — it is the graph panel's own colour set, and a directory named `canvas` inside `graph` read as a cross-feature import to both a person and the boundary test (which now resolves import specifiers to real paths rather than matching them as text, after that false positive)
- **The pipeline stages are named but not yet split into files.** Moving them to `src/markdown/passes/` turns out not to be mechanical: the five together reach 17 helpers that all live in `remark-wikilink.ts`, two of which the orchestrator also uses, so a split exports 17 internals and leaves `passes/` importing back from the module that imports it. Left as named sections in one file, which is where the readability win already landed
- **The markdown pipeline is now a named, readable list.** `remarkWikilinkInner` ran 19 stages over the document tree, but only 9 of them were named functions — the other 10 were anonymous `visit()` blocks inline in a 521-line orchestrator, so the one property that matters about them (their order) was invisible in a diff. Each is now an extracted function, verbatim, and the orchestrator is 190 lines that read as the ordered pipeline it always was. The order is load-bearing in at least one place: the comment-value pass exists to catch callout content, which is rebuilt from source and so carries no source positions — moving it before the callout stage publishes hidden comment text, and `pipeline ordering` in the test suite fails when that happens. Not every neighbouring pair is coupled, and the comment above the stages says so rather than implying it

The navbar is now the three plugins plus getting-started and the compatibility matrix. `callouts`, `transclusion` and `backlinks` moved under `markdown/guide/`, `wikilinks/getting-started` became `markdown/guide/link-resolution` (which also ends two pages in one feature both being called "Getting Started"), and `tags-daily-notes/` became `markdown/guide/tags-and-daily-notes`. The section index went: its feature table duplicated the `markdown()` docstring, so it is gone; its one unique section — vault search (`[[##query]]`) and the inline picker — moved into `link-resolution`, where it belongs. No URL was published to preserve — 0 tags, no docs domain — so this cost nothing now rather than after 1.0.0
- **`advanced.md` was titled "All Configuration Options" and omitted eight.** `vaultRoot` and `vaultRoutePrefix` were missing entirely, along with `onDataviewError`, `onUnsupportedBlock`, `enableDataview`, `enableDailyNotes`/`dailyNotes`, `enableUnlinkedMentions`, `mathEngine` and `mermaidSecurityLevel`. For a plugin whose headline is "publish an Obsidian vault", the option that names the vault was undocumented on the options page. All eight are now there, each with a section

Neither is exported from the package — they exist in `src/markdown/daily-notes.ts` and never made it onto the re-export list, so `import { applyDailyNoteTemplate } from "rspress-plugin-obsidian"` was `undefined` at runtime. It now states the subset up front, links the matrix, and says which half of the options are on by default

### Fixed

- **Dataview could forge a live `javascript:` link from note frontmatter.** A frontmatter object shaped `{ kind: link, label, href }` passed `isDataviewLink` — a structural check, not a provenance one — and `escapeHtmlAttribute` escapes `& < > "` without looking at the scheme, so `LIST evil FROM ""` published `<a href="javascript:alert(1)">`. Both the static and the `dataviewjs` renderers now pass the href through the scheme allowlist that was already written, exported and tested for the canvas renderer (`sanitizeUrl`, now in `src/escape.ts`), degrading a rejected URL to its label as plain text
- **Every page with a footnote rendered two footnotes sections.** Rspress registers `remark-gfm` first, so micromark had already turned `[^1]` into a `footnoteReference` and `[^1]:` into a `footnoteDefinition`; the plugin's text-level patterns never fired, yet its raw-source scan still populated the definition map and emitted its own `<ol class="footnotes">` on top of gfm's `<section data-footnotes>`. `[^1]` rendered no superscript at all and the back-links pointed at ids nothing emitted. Both node types are now claimed — definitions are harvested and removed so gfm has nothing left to render, and each reference emits the `<sup>` the back-link targets
- **A query string silently removed a link from the backlinks.** The graph extractor cut a destination at whichever came first, `#` or `?`, but the backlink scanner split at `#` alone, so `[text](Note.md?from=docs)` failed the `.md` test and the link appeared in no backlink panel and in no graph edge. Both now cut at the earlier of the two, which is what the compatibility matrix already claimed
- **An attachment embed rendered a dead link through Dataview.** `![[image.png]]` was recorded as a wikilink target. It can never resolve to a page, so it earned nothing as a backlink — but it did reach `file.outlinks`, where Dataview emitted `<a href="/pic.png">`, a route the site never publishes. Attachment targets are now dropped at the same point every syntax commits its target, keyed on the shared media-extension tables so a prose title like `Chapter 1. Introduction` still resolves
- **An inline footnote dropped a neighbouring `[^1]` and flattened the surrounding text.** The rebuild walked only the flattened character stream, so a node contributing no characters of its own (a `footnoteReference`) was silently discarded and a sibling `**bold**` run was rebuilt as plain text. The pass now keeps every child that no construct overlaps, by reference, and emits a `<sup>` for a multi-child match only from the child owning its `^`
- **A canvas note title containing a dot was read as a file extension.** `/\.[^/]+$/` treated `Chapter 1. Introduction` as a file called `Chapter 1` with extension `. introduction`, so `![[Chapter 1. Introduction]]` missed the note index and silently degraded to a plain link. A trailing dot-segment now only counts as an extension when it is short and alphanumeric
- **A block reference inside a canvas card fell back to the whole note.** `extractBlockSection` takes the bare block id and prepends the `^` itself when it matches the marker line, so the `#^id` subpath arrived as `^id`, matched nothing, and the embed silently inlined the entire file. The shared section slicer now strips the caret before delegating
- **A sentence-final period was swallowed into an inline Dataview field.** The identifier class allowed a trailing `.`, so `its folder is = file.folder.` resolved a field named `file.folder.`, matched nothing, and rendered as literal text at the end of a sentence. A dot now only continues an identifier when a name follows it
- **`enableDataview` silently broke inline math.** The inline-expression pass matched the `= mc` inside `$E = mc^2$` and split the text node around it, so the math pattern could no longer find both delimiters in one run and the math rendered as literal `$…$`. A pass that resolves nothing now leaves the node whole instead of rebuilding it identically
- **Every canvas heading deep-link was broken.** File-card links were built as `route + node.subpath`, so `{"subpath": "#Getting Started"}` pointed at a fragment the note page never emits — `slug()` gives `getting-started`. Both call sites now go through one `anchorHref` helper shared with the in-card markdown path, which keeps block references (`#^block`) encoded as they were
- **A loose Mermaid security level leaked into the next route.** The level is module-global and was only ever overwritten, never reset, so an unstamped set of blocks — a canvas board, which emits no stamp — inherited whatever the previous page configured. `renderMermaidBlocks` now re-derives the level from the blocks it is about to render and falls back to `strict`
- **One malformed card lost an entire canvas board.** Parsing was strict and total, so a single node with an unknown type, a non-finite coordinate or a duplicated id aborted the whole board and every other card on it stopped rendering. A node or edge that fails validation is now dropped and reported by name and reason on the console, a duplicate id keeps the first, and an edge whose endpoint was dropped goes with it — the last check is what stops the tolerance from cascading back into a hard failure. Only a structurally broken document (unparseable JSON, `nodes` not an array, a malformed `assets`/`notes` map) still throws, because there is no partial reading of one worth rendering
- **Canvas text cards ignored `==highlights==`.** Every other inline construct the Markdown plugin handles rendered in a card, but highlights were left literal. The card renderer now uses the same pattern, including the `====` exemption and inline-code protection, so a card and a note page cannot disagree about where a span ends
- **Reference-style links produced no backlink.** A `[r]: Note.md` definition is a link the graph extractor already counted and the resolver already rewrites, so excluding it made the two subsystems disagree about the same vault — a page reachable only through a reference link appeared to have no incoming edges in one view and none in the other. Definitions now feed the same normalizer as inline Markdown links, with footnote (`^[…]`) and citation (`~[…]`) labels excluded so neither becomes a page link
- **A canvas card ignored an embed's heading fragment.** `![[Note#Heading]]` written inside a text card inlined the whole note and dropped the fragment, while the same embed on a note page sliced the section. Both now share one node-free slicer (`src/markdown/transclusion.ts`), so a card and a note page cannot drift; a subpath the note does not contain falls back to the whole note rather than rendering an empty card
- **An inline Dataview expression mangled the surrounding prose.** `expressionStart` pointed at the `=` rather than past it, so the cursor under-advanced and the tail of the expression was re-emitted as literal text — `= file.name` rendered as `…index</span>me` — and the error branch pushed an overlapping slice, duplicating characters. Both ends now derive from the match, an expression resolving to nothing is left exactly as written instead of collapsing into an empty span, and only an expression that genuinely throws is reported through `onDataviewError`
- **A CRLF vault silently lost heading transclusion.** `extractHeadingSection` split on `"\n"` and matched ATX headings with a regex that cannot cross `\r`, so `![[Note#Heading]]` degraded to a plain link on any note authored on Windows — a functional difference, not cosmetic. Both section extractors now split on `/\r?\n/`
- **CRLF leaked into emitted HTML.** Micromark keeps CRLF inside multi-line text and code values, so a Windows-authored vault emitted `<p>first\r\nsecond</p>` and a byte-diff against Linux. Values are normalised at the end of every pass depth (including callout content and transcluded subtrees, which are rebuilt from source slices), so the same vault produces the same bytes on every platform
- **The coverage gate could not run on Windows.** It read lcov `SF:` values verbatim, compared them against `path.join`-built module lists and flushed on the exact string `end_of_record`, so a Windows report (backslashes, CRLF) made every module look unmeasured. Paths are now folded to repo-relative forward slashes and lines split tolerantly — verified by running the gate against the real report, a backslash+CRLF rewrite of it, and an absolute-path rewrite: identical output in all three
- **Canvas symlink containment compared realpaths with `path.sep`.** `realpathSync` can return an extended-length `\\?\C:\…` (or `\\?\UNC\…`) path on Windows, so a mixed pair never matched; the prefix is now normalised on both sides, and the raw realpath is still what gets read
- **macOS Unicode normalisation was one-sided.** Index keys were folded to NFC but the readers were not, so an NFD filename on disk never matched an NFC wikilink. The key builders, the resolver's key derivation and the mention matcher all fold now; absolute paths are deliberately untouched
- **`isPathInsideRoot` was case-sensitive**, which silently picked the wrong index root on a case-insensitive filesystem; it compares case-insensitively on win32/darwin (platform injectable, so tests do not mutate `process.platform`)
- **POSIX-only shell dependencies.** `build` ran `node -e "…rmSync…"` through whatever shell owned the quoting → `scripts/clean.ts`; `test:publish` used the `VAR=1 cmd` prefix → `scripts/test-publish.ts`, which asserts the build produced `dist/index.js` (a bare `bun test` still reports a counted skip on a clean checkout, but the release path can no longer pass while the packed-artifact contract goes unchecked); the Playwright web server was `python3 -m http.server` → `bunx serve` (same port and semantics); the publish test spawned `npm` (a `.cmd` shim on Windows) without a shell and created a directory symlink that needs Developer Mode → `shell: true` on win32 and a junction, with `tar.exe` named explicitly; CI's bash-only steps now say `shell: bash`
- Links inside canvas cards are clickable again. Claiming pointer capture on `pointerdown` retargets the compatibility click to the capturing wrapper (the click target is the common ancestor of the retargeted `mouseup` and the `mousedown`), so a file card's "open note", a link node and a wikilink in rendered markdown never navigated — in read-only mode, where card links are the primary navigation. The press now claims the pointer only once it moves past a 3px threshold, which is when it is known to be a drag; a plain click never captures. Component tests could not see this (they dispatch `click` directly), so `test/e2e/canvas-visual.playwright.ts` drives a real pointer sequence and asserts the wrapper never captures on a press — proved to fail with the old unconditional capture
- **The graph panel no longer takes focus when it mounts already open.** With `defaultOpen` it focused its own close button 150 ms after load, so it stole focus from whatever the reader had focused in the meantime — a canvas help dialog, for one — after which Escape closed the panel and left the dialog open. A panel the reader opens (click or `g`) still takes focus, and closing it still returns focus to the FAB; an auto-opened one now leaves focus alone
- **Index-route hrefs keep their trailing slash.** Rspress publishes an index page as `<route>/index.html` but normalizes a slash-less route to `<route>.html` — a file it never wrote — so every link this plugin emitted to a section index 404'd on any host that maps URLs to files: generated tag pages (`/tags-daily-notes.html`), wikilinks, Dataview links, daily-note navigation, backlinks and markdown destinations. `routeHref` now appends the slash for index pages, and the integration suite scans every internal href in the built site and asserts it maps to an emitted file (proved to fail against the old emission, which it reported as eight dead tag-page hrefs)
- **Reference-style links resolve instead of shipping a dead `.md` href.** `[label][ref]` with `[ref]: Page.md` went through Rspress untouched — the plugin's dead-link predicate had told Rspress to stand down for `.md` destinations, and the remark pass only rewrote inline links — so a typo'd or vault-relative definition built clean and rendered as a broken path. Definitions now resolve through the same ladder as inline links, and a broken one is reported through `onBrokenLink`
- **A YAML alias bomb can no longer hang or OOM a build.** js-yaml resolves aliases by reference, but the Dataview field normalizer deep-copied the graph, expanding a shared-reference DAG exponentially: ~400 bytes of frontmatter cost 2ms at depth 5 and 670ms at depth 8, per page, even with `enableDataview` off. Copies are now memoized by object identity, so a shared value is walked once per distinct value (a twelve-level bomb went from minutes/OOM to ~2.8ms) and a genuinely cyclic anchor degrades to `null` instead of overflowing the stack
- Docs: `embed` is listed in the canvas guide sidebar (the page had zero inbound links), the dead-link paragraph describes the current narrow exemption instead of a `false` default, and the index-route example uses the form that resolves
- Release and CI hardening: `release.yml` uses npm trusted publishing (no long-lived `NPM_TOKEN` in the step environment) and pins every action to a commit SHA; `ci.yml` declares `permissions: contents: read` and pins its actions too
- The coverage gate is a ratchet, not a floor: per-file 0.85, aggregate 0.97 by default, the exemption list is down to four types-only modules (each printed with its reason on every run), the dead `BELOW_FLOOR` machinery is deleted, and the branch-data path is exercised by a test
- **Security: vault frontmatter is no longer executed at build time.** `gray-matter` selects its parser from the token on the opening delimiter, and its `---js` parser is `eval`, so a note whose first line was `---js` ran arbitrary code with the build process's privileges — including on a release runner. Frontmatter now goes through `src/markdown/frontmatter.ts`, which passes an engine allow-list, refuses any marker other than empty/`yaml`/`json`, and reports the dropped metadata instead of publishing silently with an empty frontmatter object
- **Security: canvas vault reads reject symlinks.** `getSafeVaultPath` was a lexical containment check while the vault glob followed symlinks, so a link inside a shared vault could be read and published as note text or an inlined asset. The check now realpaths the root and the candidate and re-tests containment, and the glob runs with `followSymbolicLinks: false`
- Canvas drags and panning end on `pointercancel`/`lostpointercapture`, so a browser touch takeover or a native drag can no longer leave a card following the cursor with the move missing from the undo history
